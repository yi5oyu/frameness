# HARNESS.md — 이 하네스의 철학

> **하네스(harness)란:** AI 에이전트가 코드베이스를 마음대로 달리지 못하게 하는 굴레.

```
┌─ 경계 ──── 어디를 건드릴 수 있나 ──── .agents/settings.json의 source_dirs
├─ 게이트 ── 언제 건드릴 수 있나 ────── 인간 승인 + 상태 레이블
└─ 증거 ──── 무엇을 했다고 증명하나 ─── 계획 파일(ep) + 커밋 연결
```

이 셋이 하네스의 전부다. 규칙 전문: [AGENTS.md](./AGENTS.md)

## 왜 만들었나

기존 하네스·워크플로우 도구들(superpowers, GSD, BMAD, Spec-Kit …)은 훌륭하지만
공통의 문제가 있다:

| 문제 | 무엇이 잘못되나 |
|---|---|
| **규모가 크다** | 수십 개의 스킬·단계·산출물이 처음부터 전부 설치된다 |
| **안 쓰는 기능이 실려 있다** | 컨텍스트와 인지 부담을 차지하고, 무엇이 실제로 동작에 기여하는지 알 수 없게 된다 |
| **프로세스를 소유해버린다** | 도구의 절차에 프로젝트를 맞추게 되고, 절차에 버그가 생기면 고치기 어렵다 |

이 하네스는 그 반대에서 출발한다. **새 프로젝트를 시작할 때 가져가는 것은
개발에 필요한 최소 공통 구조뿐이고, 나머지는 그 프로젝트의 도메인이
실제로 요구할 때만 자란다.**

## 두 가지 목표

**① 시작 도구 — 최소 공통 코어.**
어떤 프로젝트든 개발 초기에 공통으로 필요한 것은 경계·게이트·증거 셋뿐이다.
이 셋을 파일 몇 개로 미리 만들어 두고, 새 프로젝트에 복사해 바로 쓴다.
스킬 0개로 완전하게 동작한다.

**② 추적 가능한 개발 — 계획이 곧 기록.**
개발 중의 모든 변경은 계획 파일(ep) 하나에서 시작하고 끝난다:

```
ep-{slug}.md    Purpose ──▶ Approval ──▶ Change Log ──▶ Run History
                (무엇을 왜)  (누가 승인)   (무엇이 바뀜)   (어떻게 끝남)
                     │
                     └──▶ 커밋 푸터의 ep 트레일러가 git 히스토리와 연결
완료된 ep는 done/에 쌓인다 — "이 프로젝트가 어떻게 자랐는가"의 감사 가능한 연대기
```

## 원칙 6개

1. **계약만으로 완전하다.** 하네스의 본체는 스킬이 아니라 계약(AGENTS.md)이다.
   스킬은 가속 장치일 뿐, 없어도 코어 절차 5단계로 모든 작업이 가능하다.
2. **파일만이 상태다.** 대화 맥락·세션 메모리는 상태가 아니다. 계획 파일의
   레이블이 유일한 진실이므로, 세션이 끊겨도·에이전트가 바뀌어도 이어진다.
3. **결정은 인간, 실행은 에이전트.** `[Draft]→[Approved]` 전이는 인간만 할 수
   있다. 에이전트가 스스로 승인하는 것은 복구 없는 위반이다.
4. **선언이 아니라 강제.** 규칙은 프롬프트로 선언하는 데서 멈추지 않고
   pre-commit 훅이 기계적으로 검사한다 — 무계획 소스 커밋과 증거가 모호한
   커밋은 거부된다.
5. **필요가 증명될 때만 자라고, 증명이 사라지면 제거한다.** 새 스킬·새 절차는
   명명된 고통이 실제로 나타났을 때만, 크기 예산을 정해 작게 추가한다.
   미리 크게 만들어 두지 않으며, 소비자가 사라진 구조는 걷어낸다.
6. **정본은 하나다.** 모든 규칙·형식·상태는 정확히 한 곳에 살고, 다른 모든
   곳은 포인터다. 같은 내용이 두 곳에 적히는 순간 한쪽은 언젠가 거짓말을 한다.
   예외는 기계가 파싱하는 형식의 의도적 결합뿐이며, 그 경우 "같은 커밋에서
   함께 갱신"을 명시한다.

## 무엇이 아닌가 (비목표)

- **프로세스 프레임워크가 아니다.** 요구분석→설계→구현 같은 방법론을 강요하지
  않는다. 계획 파일에 무엇을 쓸지는 프로젝트의 몫이고, 하네스는 승인과 기록만
  강제한다.
- **스킬 프레임워크가 아니다.** 작은 스킬 5종(plan·execute·review·tdd·debug)이
  동봉되지만 전부 없어도 하네스는 완전하다. 그 이상은 각 프로젝트가 자기
  도메인에 맞게 만든다.
- **CI/CD·배포 도구가 아니다.** 커밋 게이트까지가 책임 범위다.

## 구조 (전부)

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | **계약** + 코어 절차 + 스킬 표 — 유일한 상주 라우터 |
| `CLAUDE.md` | Claude Code 어댑터 — AGENTS.md import (규칙 내용 없음) |
| `HARNESS.md` | 이 문서 — 설계 철학 |
| `.agents/settings.json` | 경계(source_dirs)와 경로 — 프로젝트마다 이것만 수정 |
| `.agents/rules/global.md` | Antigravity 어댑터 — AGENTS.md 포인터 (always_on) |
| `.agents/hooks/pre-commit(.js)` | 기계적 강제 — 무계획·증거모호 커밋 거부 |
| `.agents/skills/` | 스킬 5개 정본 — plan·execute·review (사람 호출) / tdd·debug (자동) |
| `docs/plans/active/` `done/` | 계획(ep) = 증거 = 프로젝트 연대기 |

이것이 전부다. 이보다 작으면 하네스가 아니고(강제할 수 없다),
이보다 크면 아직 필요가 증명되지 않은 것이다.
