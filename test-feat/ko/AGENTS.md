[HARNESS.md](./HARNESS.md).

## 계약

### 세 가지 핵심 기능

| 기능 | 구현 위치 |
|------|----------|
| **경계 (Boundary)** — 건드릴 수 있는 곳 | `.agents/settings.json`의 `source_dirs` |
| **게이트 (Gate)** — 소스 변경 전 검문소 | 계획 파일의 상태 레이블 + 승인 기록 |
| **증거 (Evidence)** — 감사 추적 | 계획 파일의 `## Approval` · `## Change Log` · `## Run History` + 커밋의 ep 트레일러 |

### 용어

- **소스 파일:** `source_dirs` 아래의 모든 파일. 게이트 대상.
- **계획 파일:** `docs/plans/active/ep-{YYYYMMDD}-{slug}.md` — `ep-0000-template.md`를
  복사해 만든다. **파일만이 상태다** — 대화 맥락·세션 메모리는 상태가 아니다.

### 상태 (레이블 4개)

```
            (인간만)          (게이트 통과)      (인간 lgtm)
[Draft] ────▶ [Approved] ────▶ [In Progress] ────▶ [Done]
   ▲              │                  │
   └──────────────┴──────────────────┘  실패·중단·abort 시 [Draft]로
                                        롤백 + Change Log에 사유 1줄
```

`[In Progress]`만 **소스 쓰기 허용**. `[Done]` 후 계획 파일은 `done/`로 이동 —
`active/`에는 진행 중인 계획만 남는다.

### 게이트 — 소스 쓰기 전 필수 조건 (전부 AND)

```
1. 대상 경로가 source_dirs 안인가?
     → 아니면 게이트 비대상 (문서·설정은 자유)
2. 대상 파일이 ## Affected Files에 명시된 계획 파일이 존재하는가?
3. 그 계획의 상태가 [Approved] 또는 [In Progress]인가?
4. ## Approval에 인간 입력 원문 + 타임스탬프가 기록되어 있는가?
5. 같은 파일을 명시한 다른 활성 승인 계획이 없는가?
     → 한 소스 파일은 동시에 한 계획에만 속한다. 겹치면 계획을 합치거나
       한쪽을 [Done]/[Draft]로 정리한 뒤 진행하라.

하나라도 실패 → 소스 쓰기 금지. 계획을 만들거나 승인을 요청하라.
```

**승인 대기 형식** — `[Draft]` 계획을 아래로 제시하고 대기한다.
대기 중 **도구 호출 금지.**

```
승인 대기
- 계획: docs/plans/active/ep-{slug}.md
- 변경 예정 파일: {N}개
- 인수 기준: {요약 1-2줄}

| 입력 | 동작 |
|---|---|
| approved | 승인 → ## Approval 기록 → [In Progress] 전이 → 구현 |
| abort | 취소 → [Draft] 유지 |
| 그 외 | 이 화면 재표시 |
```

**계획에 없는 파일:** 계획 밖 소스 파일의 수정 필요를 발견하면 — 계획에
경로와 사유를 추가하고 재승인(`approved`) 후 수정한다.

### 증거 형식

형식의 정본은 `ep-0000-template.md`의 주석 — pre-commit 훅이 파싱하므로,
형식 변경은 템플릿·훅·이 조항을 같은 커밋에서 함께 갱신한다.

- Approval: `Approver input:`에 인간 입력 **원문을 따옴표로**, ISO8601 시각과 함께.
- Change Log: 소스 변경 **즉시** 1줄씩.
- Run History: 실행 종료마다(abort·실패 포함) 1줄.
  **기록 없는 실행은 존재하지 않은 실행이다.**

### 커밋 규약

- 커밋 시점: 코어 절차 ⑤(마감), 또는 인간이 요청한 때.
- 제목 `{type}: {요약}` (type: feat|fix|refactor|docs|chore) +
  푸터 트레일러 `ep: ep-{YYYYMMDD}-{slug}` — 커밋과 승인 증거를 연결한다.
- 계획 파일·문서만의 커밋은 트레일러 없이 가능.

### 위반 프로토콜

게이트 위반 감지 시: ① 즉시 중단 → ② `HARNESS VIOLATION` 블록으로 행위와
복구를 보고 → ③ 계획을 `[Draft]`로 롤백.

**Critical Violation (복구 없이 세션 종료):** 에이전트의 `[Approved]` 전이
또는 `## Approval` 위조 · 승인 없는 소스 수정 · Change Log 없는 소스 수정 후
은폐 · 이 계약 구역 편집.

### 강제

프롬프트 수준 강제 + **git pre-commit 훅** (`.agents/hooks/`): 승인 계획에
없는 소스 파일, 두 승인 계획이 겹치는 파일은 커밋이 거부된다.
활성화 (프로젝트당 1회): `git config core.hooksPath .agents/hooks`

## 코어 절차 — 모든 변경이 따르는 5단계

규모와 무관하게 이 절차 하나 — 계획의 크기만 달라진다 (자명한 수정 = 5줄 계획).

```
① 계획   ep-0000-template.md 복사 → Purpose·Affected Files·인수 기준 작성 → [Draft]
② 승인   승인 대기 블록 표시 → "approved" → ## Approval 기록 → [In Progress]
③ 구현   계획에 있는 파일만 수정 — 변경 즉시 Change Log 1줄
④ 검증   빌드·기존 테스트 실행 → 결과를 있는 그대로 제시 → 인간 "lgtm"
⑤ 마감   [Done] → Run History 1줄 → done/로 이동 → 커밋 (§커밋 규약)
```

- 요구가 모호하면 ①에서 먼저 질문한다 (최대 3개). 추측으로 계획을 채우지 않는다.
- 버그·예상 밖 동작: 증상 재현 → 근인(root cause) 확정 → 그 다음 수정 계획.
  근인 확정 전 코드 수정 금지.
- 실험은 경계 밖(게이트 비대상 경로)에서 — 검증된 결과의 소스 반입은 새 계획으로.

## 전역 규칙 (매 세션 적용)

- **출력 언어:** `.agents/settings.json`의 `language`. 코드 식별자는 영어.
- **시크릿 금지:** 자격증명·API 키·토큰은 코드·커밋에 넣지 않는다 —
  환경 변수와 `.gitignore`된 설정 파일로만.
- **예외 삼키기 금지:** 빈 catch 블록 금지 — 로깅하거나 전파.
- **외부 입력 방어:** null/undefined 처리를 빠뜨리지 않는다.
- **중첩 AGENTS.md:** 하위 폴더의 AGENTS.md가 그 폴더 작업 시 우선.
  하위 파일은 계약을 재기술하지 않는다 — 포인터만.

## 스킬 레이어

정본: `.agents/skills/<이름>/SKILL.md`. 아래 표가 유일한 라우터 — '언제'의
상황을 만나면 해당 정본을 읽고 따른다 (사람 호출 스킬은 요청받은 때만).
스킬은 계약을 확장할 뿐 대체하지 않는다 — 없어도 코어 절차만으로 완전하다.
스킬 추가·개명·제거 시 이 표를 **같은 커밋에서** 갱신한다 — 표가 언급하지
않는 스킬, 죽은 스킬을 가리키는 표는 거짓말하는 라우터다.

| 스킬 | 언제 | 산출물 |
|------|------|--------|
| `plan` | 요구가 모호한 작업의 계획 수립 (사람이 호출) | ep [Draft] |
| `execute` | ep의 구현 완주 (사람이 호출) | ep에 Order·Change Log·Run History |
| `review` | **새 세션에서** 구현과 독립된 리뷰 (사람이 호출) | ep에 ## Review (verdict) |
| `tdd` | 코드 작성·수정 시 자동 적용되는 규율 | red→green 테스트 |
| `debug` | 버그·테스트 실패·예상 밖 동작 시 자동 진입 | 근인 한 문단 + 회귀 테스트, 수정은 새 ep |
