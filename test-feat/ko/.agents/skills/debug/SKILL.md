# debug — 재현 → 근인 → 잠금

증상을 만나면 고치려는 손을 멈추고 이 루프로 들어온다.
(AGENTS.md 코어 절차의 근인 규칙을 상세화한 것이다.)

1. **재현 (red 고정):** 실패를 **한 명령**으로 재현되게 만든다 — 이 버그에
   확실히 실패하는 명령이 생기기 전에는 아무것도 바꾸지 않는다.
   간헐적이면 반복 실행해 실패율을 기록한다.
2. **최소화:** 입력·조건을 줄여, 실패가 유지되는 가장 작은 재현으로 좁힌다.
3. **가설 → 검증 (한 번에 하나):** "X 때문이다"를 세우고, 그것을 판별하는
   관찰(로그·중간값 출력·이등분 탐색)을 심어 실행한다. 틀리면 가설과 반증을
   기록하고 다음 가설로. 두 가설을 동시에 시험하면 어느 쪽이 판별됐는지
   알 수 없다.
4. **근인 확정:** "이 코드가 이 조건에서 이렇게 동작해서 증상이 난다"를
   한 문단으로 쓸 수 있으면 확정이다. 증상 위치와 원인 위치는 다를 수 있다 —
   고치는 것은 원인 쪽이다.
5. **수정은 게이트 뒤에서:** 근인 한 문단과 수정 방안을 담은 새 ep를 만들어
   승인 게이트(AGENTS.md 계약)로 간다. 확인용 실험은 경계 밖에서 자유.
6. **잠금:** 1의 재현 명령을 회귀 테스트로 바꿔 수정과 함께 커밋한다 —
   red였던 것이 green이 되는 것을 실행으로 확인한다.

**3회 규칙:** 같은 증상에 수정이 3회 실패하면 멈춘다. 지금까지의 가설·관찰
기록과 함께 "국소 수정이 아니라 구조 문제일 가능성"을 인간에게 보고한다.

**완료 기준:** 근인 한 문단 + 회귀 테스트 green + 수정 ep [Done]
(또는 3회 규칙 보고로 종료 — 어느 쪽이든 ep Run History에 1줄).
