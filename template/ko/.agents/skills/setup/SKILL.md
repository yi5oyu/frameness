# setup — 프로젝트 골격 확정

소스를 고치지 않으므로 ep를 만들지 않는다.

## 1. 먼저 조사한다

기존 코드가 있으면 스택은 사실이다 — 읽어서 알아낸다.
비어 있으면 결정이므로 묻는다.

## 2. 분할 기준 — AGENTS.md를 어디에 두는가

**자기 빌드·테스트 명령을 갖는 폴더마다 하나.**

- 명령이 다르면 반드시 나눈다
- 명령이 같으면 나누지 않는다 — 레이어 구분은 그 파일의 `## 구조`가 맡는다

단일 스택이면 `src/` 하나 — 루트는 계약이므로 여기에 쓰지 않는다.

## 3. 인터뷰 — 한 번에 하나, 질문마다 권고안을 붙인다

- 도메인: 무엇을 만드는가 (1-2줄)
- 분할: 위 기준으로 후보를 제시하고 확인받는다
- 폴더별 스택
- 폴더별 명령어: 빌드 · 테스트 · 단일 테스트 · 로컬 실행

## 4. 기록

폴더마다 AGENTS.md를 만든다 — 섹션은 루트 계약이 정한 대로.
맨 위에 주석 한 줄: `작업 절차는 루트 AGENTS.md. 이 파일은 이 폴더의 사실만 담는다.`
`## 구조`의 첫 줄은 그 폴더가 무엇을 담당하는가 — 도메인은 여기에 쪼개 적는다.
`## 금지`는 만들지 않는다 — 코드가 없는 시점의 규칙은 공허하다.

## 5. 검증

테스트 명령을 실제로 실행해 확인한다.
아직 실행할 것이 없으면(그린필드) 명령 옆에 `(미검증)`을 남긴다.

**끝났다고 볼 때:** 폴더마다 AGENTS.md가 있고, `## 명령어`가 실행으로 검증됐거나
`(미검증)`으로 표시돼 있다.
