# debug — 재현 → 근본 원인 → 잠금

증상을 만나면 고치려는 손을 멈추고 이 루프로 들어온다.

1. **재현 (red 고정):** **명령 하나**로 실패를 재현할 수 있게 만든다 — 이 버그에서
   확실히 실패하는 명령이 생기기 전에는 아무것도 바꾸지 않는다. 간헐적이면
   반복 실행해 실패율을 기록한다. 명령은 그 폴더 AGENTS.md의 `## 명령어`를 쓴다.
2. **최소화:** 입력과 조건을 줄여, 여전히 실패하는 가장 작은 재현으로 만든다.
3. **가설 → 검증 (하나씩):** "X 때문이다"를 말하고, 그것을 가려낼 관측
   (로그·중간값·이분 탐색)을 심고 실행한다. 틀렸으면 가설과 반증을 기록하고
   다음으로 넘어간다. 두 가설을 한꺼번에 시험하면 무엇이 가려졌는지 알 수 없다.
4. **근본 원인 확인:** "이 코드가 이 조건에서 이렇게 동작해 이 증상을 낳는다"를
   한 문단으로 쓸 수 있으면 확인된 것이다. 증상의 위치와 원인의 위치는 다를 수
   있다 — 원인을 고친다.
5. **고치기 — 어디서 발견했는지에 따라 갈린다.**
   - **구현 중** (execute 4-5단계 안에서 난 실패) → 이 루프는 원인 추적에만 쓰고,
     수정은 진행 중인 ep 안에서 한다. 확인된 근본 원인 문단은 그 ep의
     `## Decisions`에 쓴다 — Change Log 한 줄에는 담기지 않는다.
     새 ep를 만들지 않는다.
   - **마감 뒤** (`[Done]` 이후 발견된 버그) → 근본 원인 문단을 `## Decisions`에
     담고 수정 방향을 적은 새 ep를 만들고 AGENTS.md `작업 절차` 2단계로 간다.

   조사 자체는 ep가 필요 없다 — 수정만 필요하다.
6. **잠금:** 1단계의 재현 명령을 회귀 테스트로 만들어 수정과 함께 커밋한다 —
   red가 green으로 바뀌는 것을 실행으로 확인한다.

**3진 아웃:** 같은 증상에 대한 수정이 3번 실패하면 멈춘다. 가설·관측 기록과 함께
사람에게 보고한다: "국소 수정이 아니라 구조 문제일 수 있습니다."

**끝났다고 볼 때:** 근본 원인 문단 + 회귀 테스트 green + (마감 뒤였다면) 수정 ep
`[Done]` — 또는 3진 아웃 보고. 어느 쪽이든 ep `## Run History` 1줄.
