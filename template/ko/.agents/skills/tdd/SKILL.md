# tdd — 레드 → 그린 루프

이 루프는 승인된 ep 안에서 돈다. ep가 없거나 아직 승인 전이면 RED를 시작하기
전에 AGENTS.md `작업 절차` 1-2단계로 간다.
테스트 파일은 대응하는 소스가 승인돼 있으면 함께 승인된 것이다.

구현은 이 루프의 반복이다. 리팩터링은 루프 밖에서 — 전부 green이 된 뒤에 한다.

## 루프

1. **RED:** 실패하는 테스트를 하나 쓰고 **실행해서 실패를 본다.**
   실패를 본 적 없는 테스트는 믿을 수 없다.
2. **GREEN:** 그것을 통과시키는 최소 구현만 쓴다. 다음 테스트를 미리 대비하지
   않는다 — 이 red를 green으로 바꿀 만큼만.
3. 반복 — 한 번에 한 조각: 테스트 하나 → 구현 하나.

실행 명령은 그 폴더 AGENTS.md의 `## 명령어`를 쓴다. 추측하지 않는다.

## seam — 테스트가 붙는 자리

테스트는 공개 인터페이스(**seam**)만 겨냥한다. 시작 전에 ep의 기준에서 이번
작업의 seam 목록을 뽑고, 목록 밖 내부 구현에는 테스트를 쓰지 않는다.
기준마다 seam 위의 테스트가 최소 하나 있어야 한다.

## 안티패턴 (헷갈리면 [anti-patterns.md](./anti-patterns.md)와 견줘본다)

- **구현 결합** — 내부 협력자를 목킹하거나 비공개 함수를 들여다보는 것.
  판별법: 동작은 그대로인데 리팩터링만으로 테스트가 깨지면 이것이다.
- **동어반복** — 코드와 같은 방식으로 기댓값을 계산하는 것
  (`expect(add(a,b)).toBe(a+b)`). 기댓값은 독립된 출처에서 온다
  (명세의 구체적 숫자, 손으로 푼 예시).
- **수평 분할** — 테스트를 전부 먼저 쓰고 구현을 나중에 몰아 쓰는 것. 상상한
  동작을 검증하게 된다. 언제나 수직으로 — 한 번에 한 조각.

**끝났다고 볼 때:** 기준마다 대응하는 테스트가 있고 · 전부 green이고 · 변경마다
ep Change Log 1줄이 있고(절차 3단계) · 기준 줄에 확인 근거가 적혀 있다.
