# AGENTS.md

## 작업 절차

계획(ep) = `docs/plans/active/ep-{YYYYMMDD}-{slug}.md` — `ep-0000-template.md`를
복사해 만든다. **계획 파일만이 상태다.**

ep는 대화로 소스 변경에 합의한 뒤에 만든다 — 질문·조사·논의 중에는 만들지
않는다. 만든 뒤 `docs/plans/` 안은 승인 없이 쓴다.

1. **계획** — 대화에서 합의한 내용으로 템플릿을 채운다. 관련 코드를 읽고
   `## Acceptance Criteria`는 판정 가능하게. 모호하면 ep 전에 대화에서 묻는다.
2. **승인** — 계획 경로·파일·기준을 제시하고 대기한다. **대기 중 도구 호출 금지.**
   승인되면 파일·기준 사본을 `## Approval`에 남기고 Status를 `[Approved]`로 바꾼다.
3. **구현** — 승인된 파일만, 기준에 필요한 만큼만 고친다. ep는 한 번에 하나씩
   진행한다. 첫 소스 변경 직전에 `docs/plans/` 밖에 커밋 안 된 변경이 있으면
   멈추고 사람에게 보인다 — 유지·폐기는 사람이 정한다. 그다음 지금 브랜치를
   `**Branch:**`에 적고 Status를 `[In Progress]`로 바꾸고, 변경 즉시
   `## Change Log` 1줄.
4. **검증** — `## Approval`의 기준을 하나씩 확인해 `## Acceptance Criteria`에
   체크하고, 통과·실패와 커밋 메시지 안을 함께 제시한다. 사람 승인 — 또는 리뷰
   요청: Status를 `[In Review]`로 바꾸고 새 세션의 `review`를 기다린다.
   `APPROVED`면 다시 제시해 승인받고, `NEEDS_REVISION`이면 `[In Progress]`로
   되돌려 같은 ep에서 고치고 다시 검증한다.
5. **완료** — 리뷰했다면 `## Review`의 마지막 판정이 `APPROVED`일 때만. Status를
   `[Done]`으로 바꾸고 `done/`으로 옮긴 뒤, Change Log에 오른 파일과 이 ep 파일만
   경로를 지정해 커밋 (제목 한 줄 + 푸터 `ep: {slug}`).

- 계획(ep)에서 `## Approval`·`## Change Log`·`## Review`·`## Run History`는 append 전용이다
  — 지난 줄을 고쳐 현실에 맞추지 않는다. 나머지 섹션은 제자리에 채운다.
  Status와 기준 체크박스는 갱신하되, Status는 그 상태를 만든 변경보다 먼저
  기록한다. `## Affected Files`에 파일을 더하는 것은 재승인 대상이다.
- 갈림길에서는 택한 것과 버린 대안·그 이유를 `## Decisions`에 남긴다 — 코드에서
  복원되지 않는 것은 버린 쪽이다.
- 애매하면 승인이 아니다 — 재제시한다. 중단으로 읽히면 중단한다.
- 실행이 끝날 때마다 `## Run History` 1줄 — 완료·중단·실패 모두.
- 사실(`## 명령어`·`## 구조`·`## 금지`)은 이 파일 아래에 담는다 — 하위 AGENTS.md를
  만들지 않으므로 가장 가까운 AGENTS.md는 언제나 이 파일이다. 계획 단계에서 읽고,
  검증은 걸친 폴더 전부의 `## 명령어`를 실행한다.
