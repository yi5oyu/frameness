2. **승인** — 계획 경로·파일·기준과 작업할 브랜치를 제시하고 대기한다. 브랜치는
   기능 브랜치 위면 그 브랜치를 이어 쓰고, 기본 브랜치 위면 새 기능 브랜치를
   제안한다 — 다른 기능으로 나누는 것은 사람이 말할 때만. **대기 중 도구 호출 금지.**
   승인되면 파일·기준·브랜치 사본을 `## Approval`에 남기고 Status를 `[Approved]`로
   바꾼다.
3. **구현** — 승인된 파일만, 기준에 필요한 만큼만 고친다. ep는 한 번에 하나씩
   진행한다. 첫 소스 변경 직전에 `docs/plans/` 밖에 커밋 안 된 변경이 있으면
   멈추고 사람에게 보인다 — 유지·폐기는 사람이 정한다. 그다음 승인된 브랜치를
   열거나 그 브랜치로 옮겨 `**Branch:**`에 적고 Status를 `[In Progress]`로 바꾸고,
   변경 즉시 `## Change Log` 1줄. 기본 브랜치에는 커밋하지 않는다.
4. **검증** — `## Approval`의 기준을 하나씩 확인해 `## Acceptance Criteria`에
   체크하고, 통과·실패와 커밋 메시지 안을 함께 제시한다. 사람 승인 — 커밋과
   push까지 포함한다. 또는 리뷰 요청: Status를 `[In Review]`로 바꾸고 새 세션의
   `review`를 기다린다. `APPROVED`면 다시 제시해 승인받고, `NEEDS_REVISION`이면
   `[In Progress]`로 되돌려 같은 ep에서 고치고 다시 검증한다.
5. **완료** — 리뷰했다면 `## Review`의 마지막 판정이 `APPROVED`일 때만. Status를
   `[Done]`으로 바꾸고 `done/`으로 옮긴 뒤, Change Log에 오른 파일과 이 ep 파일만
   경로를 지정해 커밋 (제목 한 줄 + 푸터 `ep: {slug}`)하고 push한다. push한 이력은
   다시 쓰지 않는다. PR은 열지 않는다 — ep 완료는 기능 완료가 아니다.

**PR** — ep 절차 밖이다. 사람이 기능이 끝났다고 말할 때만 연다: 브랜치가 걸친
폴더 전부의 `## 명령어`를 실행 → `git log {기본 브랜치}..{브랜치}`의 `ep:`
트레일러로 이 브랜치의 ep를 모아 PR 제목·본문(ep마다 Purpose 한 줄 + 검증 결과)을
제시하고 대기 → 승인되면 PR을 연다. 머지는 사람 몫이다.
(git 전략: GitHub Flow — 이 2~5단계와 PR이 그 전부다)
