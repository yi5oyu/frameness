# frameness

AI 에이전트가 코드를 수정하기 전에 **사람이 무엇을 왜 바꾸는지 승인**하게 하고 모든 계획, 승인, 검증, 의사결정 과정을 계획 파일에 기록해 세션이 끊겨도 **재현 가능하고 추적 가능한 개발 프로세스**를 만드는 것을 목표로 합니다.

[하네스 설계와 구조](./HARNESS.md)

## 계획 파일 (ep)

하나의 목표를 위한 계획 파일을 작성하고 실행의 모든 과정을 그 파일에 기록해 세션이 끊기든 모델이 바뀌든 파일과 코드만으로 작업을 이어받을 수 있습니다.       
완료된 뒤에는 이 코드가 어떤 과정에서 나왔고 무엇을 왜 그렇게 만들었는지 따라 판단할 수 있는 문서로 남습니다.

```
docs/plans/active/ep-{YYYYMMDD}-{slug}.md
docs/plans/done/ep-{YYYYMMDD}-{slug}.md
```

2. 프로젝트의 아키텍처마다 다른 기술 스택과 환경을 위한 하위 AGENTS.md를 생성합니다.

AGENTS.md 공식 가이드: [https://agents.md](https://agents.md/)

### 실행 흐름

1. **계획** - 템플릿을 복사해 목적, 변경 대상 파일, 기준 등을 계획한다.
2. **승인** - 계획 경로, 파일, 기준 등을 제시하고 기다린다.
3. **구현** - 승인된 파일만 기준에 필요한 만큼만 구현한다. (변경 즉시 내용 기록)
4. **검증** - 완료 기준을 항목마다 통과/실패로 판정하고 판단한 근거를 남긴다.
5. **완료** - [완료] → done/으로 이동 → 커밋

```
     plan                         tdd          debug
      │                            │             │
      ▼                            ▼             ▼
  [계획] ────▶ [승인] ────▶ [구현] ────▶ [검증] ────▶ [완료]
                  └─────────── execute ──────────────┘
                  ▲                                  ▲
               승인 필요                           승인 필요
```

## 스킬

- 사용자 호출에 의해서 실행되어야할 스킬

| Skill            | 역할                       |
| ---------------- | ---------------------------------- |
| `setup`          | 설치 직후 or 새 스택 폴더를 추가할 때 |
| `plan`           | 인터뷰로 계획 파일(ep) 작성한다.       |
| `review`         | 다른 세션에서 계획을 다시 검증한다.      |
| `execute`        | 계획 파일을 실제 구현한다.             |

- 모델에 의해 실행되는 스킬

| Skill            | 역할                       |
| ---------------- | ---------------------------------- |
| `tdd`            | `execute`의 구현 단계에서 승인된 계획 안에서만 실행, 승인 전이면 절차로 되돌린다.      |
| `debug`          | 테스트 실패 후 원인이 모호할 때 실행, 계획이 완료된 이후에 발견한 버그는 새 계획 파일 작성 후 수정 |
